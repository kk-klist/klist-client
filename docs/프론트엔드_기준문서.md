# 🧭 Klist+ 프론트엔드 기준 문서

> 팀 표준(React 컨벤션 문서) 기반으로 만든 **공용 스캐폴드(`klist-frontend/`) 사용 설명서**.
> 각자 맡은 페이지는 이 문서대로 자기 기능 폴더 안에서만 작업하면 충돌 없이 합쳐진다.

---

## 1. 실행 방법 (Quickstart)

```bash
cd klist-frontend
npm install
npm run dev        # http://localhost:5173 (포트 고정 — 카카오 SDK 도메인 등록 때문)
```

지도 페이지까지 보려면 백엔드도 실행:

```powershell
cd klist-map-backend
.\run.ps1          # http://localhost:8080
```

```

│   ├── store.js          # Redux (auth 만 등록돼 있음)
│   ├── router.jsx        # ★ 새 페이지는 여기에 라우트 1줄 추가
│   └── queryClient.js
├── features/
│   ├── map/      ✅ 완성 (백엔드 연동) — 지도 담당
│   ├── auth/     🚧 깡통 — 인증 담당 (LoginPage + authSlice)
│   ├── profile/  🚧 깡통 — 프로필 담당 (MyPage)
│   ├── ticket/   🚧 깡통 — 티켓 담당 (TicketPage)
│   └── chat/     🚧 깡통 — 챗봇 담당 (ChatPage)
├── shared/
│   ├── api/client.js     # axios 단일 창구 (토큰/에러/401 자동 처리)
│   ├── components/       # AppLayout(하단탭)·Spinner·EmptyState·PageStub
│   └── utils/cn.js       # 조건부 class 결합
└── styles/index.css      # Tailwind 지시문 + 전역 (새 .css 만들기 금지)
```

### 폴더 규칙 (요약 — 위반 시 리뷰 반려)

1. 파일은 **자기 기능 폴더 안에만** 만든다. 2개 이상 기능에서 실제로 쓰게 되면 그때 `shared` 로 옮긴다.
2. `shared` 는 특정 기능을 알면 안 된다 (기능 분기 금지).
3. **다른 기능 폴더를 import 하지 않는다.** 필요하면 `shared` 로 옮기거나, 로그인 사용자는 `useSelector((s) => s.auth.user)` 로.
4. import 방향: `app → features → shared` 한 방향만.

## 4. 내 페이지 만드는 법 (5단계)

깡통 페이지(`PageStub`)를 지우고 아래 순서로 채운다. 예: 티켓 담당.

**① API 파일** — `features/ticket/ticketApi.js`

```jsx
import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';
import { client } from '@/shared/api/client';

const fetchTickets = () => client.get('/api/v1/tickets'); // 조회 함수 = fetchXxx
const createTicket = (request) => client.post('/api/v1/tickets', request);

export function useTicketsQuery() {
  return useQuery({ queryKey: ['ticket'], queryFn: fetchTickets }); // queryKey = ['기능명']
}
export function useCreateTicketMutation() {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: createTicket,
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ['ticket'] }), // 필수!
  });
}
```

**② 페이지 컴포넌트** — `features/ticket/TicketPage.jsx` (조회 4단계 상태 순서대로)

```jsx
import { useTicketsQuery } from './ticketApi';
import { Spinner } from '@/shared/components/Spinner';
import { EmptyState } from '@/shared/components/EmptyState';

export default function TicketPage() {
  const { data: tickets, isLoading, isError } = useTicketsQuery();
  if (isLoading) return <Spinner />;
  if (isError) return <EmptyState message="목록을 불러오지 못했습니다." />;
  if (tickets.length === 0) return <EmptyState message="티켓이 없습니다." />;
  return (
    <ul>
      {tickets.map((t) => (
        <li key={t.id}>{t.title}</li>
      ))}
    </ul>
  );
}
```

**③ 폼이 있으면** — `ticketSchemas.js`(zod) + `useCreateTicket.js`(커스텀 훅). 백엔드 Bean Validation 과 규칙을 1:1로 맞춘다. `useState` 수동 폼 금지.

**④ 라우트 등록** — `app/router.jsx` 에 한 줄 (이미 등록돼 있으면 생략).

**⑤ 확인** — `npm run dev` 로 화면 확인, `npm run build` 통과 확인.

### 꼭 지킬 것 (팀 표준 요약)

- 서버 데이터를 `useState`/Redux 에 **다시 저장하지 않는다** (Query 캐시에서 바로 꺼내 씀).
- axios 직접 호출 금지 — 반드시 `client` + `xxxApi.js` 훅 경유.
- 에러 분기는 `code` 로만. 문구는 서버 `message` 그대로 노출.
- 401 분기 금지 (client.js 가 전역 처리 → /login 리다이렉트).
- 색상 코드 직접 사용 금지 — config 색상 이름만.
- 페이지 번호/검색어는 URL 쿼리스트링(`useSearchParams`).
- 네이밍: `XxxPage.jsx`(default export) / `useXxxQuery`/`useXxxMutation` / `use동사대상.js` / `{기능}Api.js`.

## 5. 인증 연동 규약 (인증 담당 ↔ 전원)

- 로그인 성공 시 `localStorage.setItem('accessToken', ...)` — 이후 **모든 API 에 자동 첨부**됨 (client.js).
- 사용자 정보는 `dispatch(setUser({...}))` — 다른 기능은 `useSelector((s) => s.auth.user)` 로 **읽기만**.
- 지도 API 의 `userId` 파라미터(현재 데모 1 고정)는 로그인 붙으면 토큰 기반으로 교체 예정.

## 6. 지도(feature/map)의 예외 사항

지도는 카카오 SDK 이벤트(idle/마커 클릭)와 얽혀 **Query 훅 대신 mapApi 함수 직접 호출**을 허용한다. 다른 기능은 이 예외를 따라하지 않는다. 지도 수정은 지도 담당에게.

### 다국어(lang) 상태 — 지도 페이지 로컬 관리 (임시)

TourAPI 는 `ko/en/ja/zh-CN/zh-TW` 5개 언어를 지원한다. 지금은 지도 페이지 하나에서만 언어를 바꾸므로 **URL query param `?lang=en` 으로 관리**한다 (`useMapPage.js` 의 `resolveLang`).

**추후 확장 계획 (마이페이지/온보딩 담당자 몫)**

- 로그인 후 온보딩(국적/선호언어 선택) 화면에서 초기 언어를 정하고 `localStorage` or Redux `auth` 슬라이스에 저장
- 마이페이지 Language 설정에서 변경 가능
- 지도 페이지가 그 전역 값을 읽도록 `useMapPage` 수정 (`useSearchParams` → 전역 셀렉터로 교체 1줄)
- URL query 방식은 계속 fallback 으로 유지 (딥링크 지원)

**⚠️ 데이터 소스 주의**
현재 `TOUR_SERVICE_KEY` 는 한국어(KorService2)만 승인됨. 영어/일본어/중국어(간체·번체) 로 호출하면 백엔드가 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 반환 → 502. 다국어 데모 하려면 한국관광공사 공공데이터포털에서 각 언어 서비스(EngService2/JpnService2/ChsService2/ChtService2) 별도 활용신청 승인 필요.

## 7. 챗봇 ↔ 지도 연동 계약
